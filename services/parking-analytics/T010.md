# S4 T010 integration based on T008

S4 now refreshes and preserves independent catalog, tariff and aggregate-occupancy
snapshots, and can consume dataset events from its own PostgreSQL. This extends the
working T039–T045 implementation. It does not claim completion of T010 for other services.

## T008 traceability

| T008 requirement | S4 implementation |
|---|---|
| [S4 contract](../../docs/api/contracts/S4-Parking-Analytics.md): catalog/rates survive occupancy failure | Independent stream validation and availability, with usable catalog/pricing preserved during occupancy outages. |
| [Ownership §4.4](../../docs/architecture/Service-Data-Ownership.md): S4 owns facilities, tariffs and derived occupancy | Dedicated optional S4 PostgreSQL intake snapshots; S4-only bounded SQLite fallback; no registry/S1/S2/S3 data access. |
| [Dependency register](../../docs/architecture/External-Data-Dependencies.md): normalized provider adapter, provenance and timestamps | Versioned catalog/tariff/aggregate inputs; finite I/O, source dates preserved, unknown provider dates remain null. Fixtures/files remain simulated. |
| Idempotent background consumers and replica-safe refresh | Content revisions, transactional update hints, authoritative storage rereads and periodic/reconnect reconciliation. |
| Separate occupancy/pricing freshness, truthful degraded responses | Existing 300-second occupancy and 24-hour price rules retained; stale/cached data cannot imply available spaces. |
| No raw location history in public caches | Only catalog, tariffs and derived facility aggregates are persisted. The estimator remains computation-only. |

## Three independent streams

`app/datasets.py` defines normalized inputs, rejecting undeclared fields:

- **catalog**: schema version, source, explicit simulation flag, nullable provider
  update date and a nonempty list of unique facility IDs. Coordinates/capacity use
  the existing Facility model.
- **pricing**: schema version, source, simulation flag and a map of facility IDs to
  existing CAD rate/fee shapes, tax information and nullable source-update dates.
  Unknown pricing remains unknown; duplicate tariff IDs and rates without currency
  are rejected. Pricing for unknown facilities is not installed.
- **occupancy**: the existing aggregate `FeedSnapshot`, with schema version and
  bounded item count. Capacity/ratio consistency, duplicate/unknown facility IDs
  and future observation dates are validated against the current catalog.

Each payload is limited to **8 MiB**. Catalogs and occupancy have at most **10,000**
facilities; tariff maps have at most 10,000 facilities, each with at most 100 rates
and 100 fees. These are bounded implementation limits, not provider-volume promises.
Files used by the local adapters must explicitly declare simulated data. Synthetic
catalog source labels are kept visibly simulated in the API.

Occupancy refresh failures do not discard catalog or rates. Tariff failures do not
discard occupancy. Invalid replacements preserve their last usable independent
snapshot. A catalog capacity/ID change invalidates incompatible occupancy so old
counts cannot be applied to a changed facility.

## PostgreSQL pub/sub and durable intake

The optional `parking_datasets` table contains only the latest snapshot for each of
the three streams, with its content revision and actual ingestion receipt time.
It is an S4-owned intake projection, separate from the registry and other services.
The existing geographic calculations remain in memory; this work does not add a
new search algorithm or claim a complete production PostGIS/tariff-history model.

An operator publishes approved normalized inputs using `tools/import_dataset.py`.
Changed content is upserted and announced in the same PostgreSQL transaction:

```json
{
  "schema_version": 1,
  "stream": "pricing",
  "revision": "<64-character SHA-256 digest of the normalized payload>"
}
```

Channel: **`s4_parking_updated_v1`**. Notifications contain no raw observations,
credentials, provider payload or private user identifiers. The database's S4
credentials authorize publication; this is not a new public HTTP submission API.

Subscribers validate the hint and reload current snapshots from S4 storage.
Repeated identical publication does not change the snapshot, receipt timestamp or
emit another notification. Old/duplicate hints cannot roll data back because current
storage is authoritative. Notifications are not durable: startup, periodic and
reconnect reconciliation recover missed hints and updates from legacy writers.
The event channel and intervals are S4 implementation choices within the T008
boundaries, not a claim that T008 selected a global broker product.

## Cache, freshness and outage behavior

`PARKING_CACHE_PATH` stores at most three bounded normalized stream snapshots, scoped
to the configured source, plus the existing single aggregate-cache record. No raw
subjects/observations are stored. Separate cache paths are required per instance.
Valid catalog and tariff snapshots survive process restart even when PostgreSQL is
down. An invalid independent cache row does not hide the other valid streams.

Source `observed_at` / `source_updated_at` values are distinct from receipt time.
Unchanged inputs do not continually rewrite `service_updated_at`; restored timestamps
are preserved across restarts. Source-refresh health timestamps describe checks,
not new provider observations. Unknown provider dates remain null.

Occupancy is stale after 300 seconds of observation age. After its configurable
maximum **retained-cache age** (default 24 hours since the snapshot receipt), counts
become unavailable/null; known facilities and tariffs remain visible. Pricing older
than 24 hours, or with unknown source dates, remains visibly stale. Catalog/rates
are not silently deleted just because live occupancy is unavailable.

Reads use installed snapshots and do not call PostgreSQL/providers. A missing
essential catalog makes `/ready` return 503; a usable retained catalog supports the
documented degraded state. Authentication remains independent and still fails closed
when required trusted signing keys cannot be obtained.

Settings:

| Variable | Default | Meaning |
|---|---|---|
| `PARKING_DATABASE_URL` | unset | Optional dedicated S4 PostgreSQL intake; otherwise fixture/file mode |
| `PARKING_CATALOG_FILE` | unset | Optional normalized simulated catalog file |
| `PARKING_PRICING_FILE` | unset | Optional normalized simulated tariff file |
| `PARKING_OCCUPANCY_MODE` | `fixture` | Existing `fixture`, `file`, `unavailable` modes outside PostgreSQL mode |
| `PARKING_OCCUPANCY_FILE` | unset | Existing simulated aggregate file adapter |
| `PARKING_REFRESH_SECONDS` | `5` | Reconciliation interval, 0.1–3600 seconds |
| `PARKING_RETRY_MAX_SECONDS` | `60` | Capped exponential reconnect delay, at least the refresh interval, at most 3600 seconds |
| `PARKING_CACHE_RETENTION_SECONDS` | `86400` | Maximum occupancy cache age; positive, at most seven days |
| `PARKING_CACHE_PATH` | unset | Optional S4-owned SQLite fallback; in-memory snapshots otherwise |

Connections and metadata SQL have two-second timeouts. Notification waits are short
and shutdown is bounded. Reconnect uses capped exponential backoff with jitter.
`GET /v1/parking/ingestion/status` reports typed per-stream health, revisions, last
successful checks, event counts and configured persistence. It requires JWT identity
and omits credentials, source paths and user records.

## Run and demonstrate

Use [AUTHENTICATION.md](AUTHENTICATION.md) for Keycloak configuration and tokens.
The existing fixture workflow in [README](README.md) still works with authenticated
calls. No real provider or live feed is automatically selected or downloaded.

For PostgreSQL, populate your root `.env` as usual and set a URL-safe, private
`PARKING_DB_PASSWORD`. Keep the same password for that volume's lifetime. At the
repository root, run:

```powershell
$parkingCompose = @('-f','docker-compose.yml','-f','services/parking-analytics/compose.parking.yml','-f','services/parking-analytics/compose.parking.db.yml')
docker compose @parkingCompose up --build -d parking-analytics

# Explicitly seed simulated demo inputs; never performed automatically on startup.
docker compose @parkingCompose exec -T parking-analytics python tools/import_dataset.py --seed-demo

# Or publish an approved normalized provider snapshot from a mounted/available file.
# python tools/import_dataset.py --stream pricing --file /path/to/approved-pricing.json

$headers = @{ Authorization = "Bearer $env:PARKING_ACCESS_TOKEN" }
Invoke-RestMethod 'http://localhost:8084/v1/parking/ingestion/status' -Headers $headers | ConvertTo-Json -Depth 5
Invoke-RestMethod 'http://localhost:8084/v1/parking/facilities/demo-central' -Headers $headers | ConvertTo-Json -Depth 8
```

The optional S4 database has its own credentials/volume and is not host-published by
default. Provision the existing team Keycloak realm/client separately. An empty S4
database is unready until a usable catalog is published. Do not change a running
team database to demonstrate an outage; use the isolated verification command below.

heartbeats, PostgreSQL tariff events, duplicate publication, malformed/missed hints,
retained catalog/tariffs/occupancy after DB failure and restart, and signing-key
outage behavior. It runs existing registry tests and the T040/T044 HTTP workload.

running containers and databases remain unchanged.

long-duration load and hardened identity/storage operations remain separate
deployment work. The estimator's raw request observations remain computation-only
and never become an implicit ingestion feed.
